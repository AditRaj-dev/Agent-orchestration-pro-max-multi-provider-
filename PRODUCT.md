# Product

## Register

product

## Users

Agent Engineering OS is for software engineers and technical leads who plan, delegate, review, and ship software with several specialized AI agents. They use it during sustained engineering work, often with multiple runs, conversations, artifacts, and repositories open at once. Their primary job is to give the right agent the right context and authority, understand what is happening, and preserve decisions across handoffs.

## Product Purpose

Agent Engineering OS turns project intent into an inspectable Mastermind plan, an executable dependency graph, and a durable set of agent conversations. It should make parallel work safe, observable, and recoverable without forcing users to repeatedly restate skills, permissions, or project context.

Success means a user can create or open a repository, approve a plan, launch specialized agents on different providers and models, observe concurrent work, review artifacts and changes, and hand a curated, Memex-backed context package to another agent without losing provenance.

## Brand Personality

Precise, calm, formidable.

The product speaks like an experienced engineering operator: direct, specific, honest about uncertainty, and quiet when nothing needs attention.

## Anti-references

- Generic “AI command center” dashboards with purple/blue neon, glass panels, glowing nodes, or decorative data movement.
- Card grids that turn every concept into the same rounded rectangle.
- Enterprise administration screens that bury the active task under configuration chrome.
- A visual clone of ChatGPT that hides agent identity, permission scope, context provenance, or workflow lineage.
- Fabricated metrics, fake activity, and optimistic execution states that the daemon has not confirmed.

## Design Principles

1. **State before spectacle.** Motion and color must explain real execution, authority, or change.
2. **Authority is always visible.** Agent, provider, model, permission mode, and write scope remain inspectable wherever work can start.
3. **Provenance survives every handoff.** Conversations, memories, artifacts, commits, and workflow nodes link back to their source.
4. **Parallelism stays legible.** The interface explains why work is running, queued, blocked, serialized, or awaiting approval.
5. **Power without ceremony.** Saved agents carry their skills automatically; slash commands expose the full control surface without becoming a policy bypass.

## Accessibility & Inclusion

Target WCAG 2.2 AA. Every action must be keyboard-operable, every control must expose an accessible name and state, focus must remain visible, body text must meet contrast requirements, and color may not be the only status signal. Graph workflows require an equivalent list view. Motion must respect `prefers-reduced-motion`, and live updates must avoid disruptive announcements.
